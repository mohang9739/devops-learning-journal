## Interview Practice

### Scenario

**Question:** Users from your company's Bangalore office are reporting intermittent issues accessing an internal web application `billing.internal.company.com`. Some users can access it without problems, while others report slow loading times or receive 'ERR_CONNECTION_TIMED_OUT' or 'ERR_NAME_NOT_RESOLVED' errors. The application itself is hosted on a Kubernetes cluster in AWS and is accessible without issues from other office locations and by direct API calls from backend services within AWS.

As a Platform Engineer, walk us through your step-by-step diagnostic process. For each step, explain what actions you would take, what tools you would use, and what networking fundamentals (TCP/IP, DNS, OSI layers) you'd be validating or looking for potential issues.

### Architecture

**Question:** Your team is deploying a critical new microservice within a Kubernetes cluster that must securely and reliably connect to a third-party payment gateway API over the public internet. This gateway requires all incoming requests to originate from a fixed set of IP addresses for security and compliance, and expects high throughput with low latency. Design the network architecture for this communication path, detailing the components you would introduce *outside* the microservice pod itself to achieve these requirements. For each component, explain:
1. Its primary role in the communication flow.
2. How it contributes to meeting the requirements (fixed IP, security, throughput, latency).
3. Which OSI layers it primarily operates at, and how it leverages TCP/IP or DNS fundamentals.

### Coding

**Question:** You are a Platform Engineer tasked with improving the real-time health monitoring for a critical HTTP microservice. The service is accessible via `api.yourcompany.com` on port 8080. Users occasionally report 'host not found' or 'connection refused' errors, which your current monitoring often catches late or misdiagnoses.

Write a bash script (or a Python script) that performs a comprehensive, client-side health check for this service. The script should:

1.  **Verify DNS resolution:** Resolve `api.yourcompany.com` to its IP address. If resolution fails, report a DNS failure and exit with a non-zero status.
2.  **Verify TCP connectivity:** Attempt to establish a TCP connection to the resolved IP on port 8080. If connection fails, report a TCP connectivity issue (e.g., firewall, service not listening) and exit with a non-zero status.
3.  **Verify Application Health:** If TCP succeeds, make an HTTP GET request to `http://<resolved_ip>:8080/health` (assume this endpoint exists and returns a 200 OK for a healthy service). If the request fails or returns a non-200 status, report an application health issue and exit with a non-zero status.
4.  **Output clear success/failure messages** at each step, indicating the specific type of failure if any. If all checks pass, output a success message and exit with a zero status.

Your solution should leverage standard command-line tools (for bash) or standard libraries (for Python) and demonstrate robust error handling.
